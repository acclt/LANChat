## 本版包含

- Android 通知采集、应用允许列表、多目标定向推送，沿用现有 `/ws`；离线、失败、超时直接丢弃。
- Android／Windows 接收端展示来源 App 图标、应用名、标题和正文。App 内采用左侧图标／名称／时间、右侧标题与内容卡片的已确认布局；系统通知采用各平台允许的样式，系统发布者身份仍为 LQ Chat。
- 标准进度通知在 A 端发送前过滤，包括 0%、途中、100% 和不确定进度。清除进度条后发出的普通通知可继续处理；不推断下载结束、不生成结果、不跟踪下载任务。
- 坏图标降级为文字；不访问远端图标 URL。接收记录与聊天记录分离，同通知 key 更新原卡片及系统通知。

## 本轮修复

1. 补齐 `notification_settings`、`notification_records`、`notification_action`、`notification_test` 的精确应用权限声明，并加入桌面与移动界面的现有权限清单。没有授予额外远端页面访问权限。实际 Windows 客户端的“通知功能尚未就绪”问题已消失，通知入口和设置页面能打开。
2. 统一用户要求的 0.2 版本，Android 升级编号从 1019 提升为 1020。
3. Android 设备测试此前仍采用旧的 InstrumentationTestRunner；改为 AndroidJUnitRunner 并成功构建设备测试 APK，避免“测试源码编译了但运行器不支持已有 JUnit4 测试”的问题。
4. 新增仅限固定本机验收实例的合成回归脚本 `tests/acceptance02.cjs`，覆盖聊天、多文件上传下载、通知并发及拒绝条件；更新系统通知历史检查器对验收应用名称的判断。

## 未通过验收门槛的项目

- adb 没有连接设备，Android 设备测试仅构建，未执行。NLS 冷进程门禁、真实应用通知、进度过滤、系统通知布局、App 授权／设置桥、锁屏／息屏／Home 后台／UI 重建、SAF 文件保存、手机间多目标及防回环均需真机继续验证。
- Windows 测试曾出现系统防火墙授权窗口，已请用户处理；后续观察到提示解除，继续完成上述原生交互。电脑操作技能禁止代操作安全权限，本轮没有点击安全提示、越过提示或新增防火墙规则。
- 后续检查确认用户原有 0.19 客户端已退出，本轮没有强制关闭它。最终 EXE 已通过启动、设置保存、隐藏／恢复和本机通信；进程重启后的设置恢复、托盘菜单退出及其他完整原生流程未全部验收。一条组合回归／重启命令被执行工具的策略拒绝，没有执行，也没有把该检查记作通过。
- 没有完成真实 LAN 大文件压力、两小时混合运行或不同 Windows 系统缩放比例测试。本机回环速度不能代表 Wi-Fi 和手机负载表现。
- 自定义进度通知没有标准字段时不保证识别；来源 App 完成／失败时仍带有效进度字段，也会被过滤。

## 原架构保护与清理

本轮与开始前备份逐文件核对：CoreRuntime、WebSocket／文件处理源码、LanChatForegroundService 和源 Manifest 未变。仍为 START_NOT_STICKY、stopWithTask=true，没有新加 LanChat 的开机恢复、冷启动或后台协调器。

合并 Manifest 中已有 Tauri 通知插件的 LocalNotificationRestoreReceiver 及 boot 权限，在旧 v4 APK 中就存在，本轮未新增；不能把它误写成新增了 LanChat Core 开机自启，也不能宣称 APK 完全不含任何 boot 相关声明。

本轮只使用临时数据库与合成文件，没有读写用户正在使用的聊天数据库。旧客户端文件保留。

收尾记录：合成 UI 预览服务已停止，三个预览页已关闭，视口已恢复；仅移除了明确命名的合成系统通知，重新检查这些通知的历史为空。开始菜单快捷方式已按本轮之前的备份恢复，文件哈希一致。

最终 0.2 EXE 的临时验收实例仍在运行（验收时 PID 13384，数据库为 `%TEMP%/lanchat-v4-icons-native-check`），已请用户从托盘正常退出。正式使用交付 EXE 前请先退出该实例，否则单实例机制会恢复临时验收窗口。没有强制结束用户客户端，没有修改原聊天数据库，也没有修改原配置文件中的端口或关闭到托盘设置。
